# 员工考勤与运营任务开发交接

交接日期为 2026 年 11 月 12 日。Web 首期代码已从会话记录恢复，位于本地独立工作树的 codex/employee-operations-recovery 分支。恢复补丁按当前本地 V2 源码生成，适用目标是 Documents 下的蓝猫运营系统目录。该目录有在途改动，恢复版也尚未形成生产发布提交。

## 归档材料

- employee-operations-requirements.md 记录业务需求、权限边界和验收口径。
- employee-mini-taro-plan.md 记录独立微信小程序的选型、Web 功能覆盖范围和交付顺序。
- employee-attendance-pilot.md 记录 Web 联调和门店打卡试点操作。
- employee-operations-recovery.patch 包含恢复源码、17 个新增迁移及交接文档。SHA256SUMS 用于核对归档文件。
- CURRENT_STATE.md 和 DECISIONS.md 记录当前开发、验证状态及独立小程序决策。

新会话优先使用仍可访问的恢复工作树。若工作树不可用，先确认原 V2 源码所在目录及未提交改动，使用 git apply --check 检查补丁。检查成功后，在基于对应 V2 源码的独立工作目录应用补丁。补丁依赖当前 V2 源码基线，旧远端的干净 main 不能单独作为恢复基线。

## 已验证

- 冻结锁文件安装、Prisma Client 生成、前后端类型检查及构建通过。
- V2 回归及边界检查通过。隔离 MySQL 8 空库成功执行全部 63 个迁移，Prisma 报告数据库为最新。
- 合成数据的服务层验收覆盖重复派发去重、并发认领、检查项转整改、打回通知、旧提交复核拦截、考勤越权拒绝、补卡审批和月度 CSV。
- 本机联调使用了匹配版本的 Sharp arm64 二进制。重新装依赖时可先在服务端执行 node -e "require('sharp')" 检查本机运行时。

## 新会话接手顺序

1. Web 完成浏览器及 HTTP 验收，覆盖撤权后的旧会话、私有照片上传和访问、循环派发、抄送及剩余管理操作。遇到问题在恢复分支修复并补回归。
2. 整理可审查的发布提交，核对生产当前版本和已应用迁移，再制定增量迁移、备份、回滚和单店试点方案。当前恢复版尚未部署。
3. 并行搭建 Taro 4、Vue 3、TypeScript 工程和隔离环境 API，先开发登录、考勤及任务入口。新建独立微信小程序，最终覆盖 Web 全部业务模块。独立 AppID、测试 HTTPS 域名和微信后台配置用于真机与体验版联调。
4. 隔离环境验证后，再安排生产接入和真实门店试点。工资联动、员工网络强校验及照片抽查按需求文档的条件验收。
