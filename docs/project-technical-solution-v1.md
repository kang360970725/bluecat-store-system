# 项目技术方案 V1

## 1. 文档目的

本文档用于确定新项目的启动技术方案，作为后续开发、沟通、扩展和新会话续接的统一基线。

当前结论以“尽快启动、降低维护成本、兼顾后续扩展”为目标，不提前引入不必要的分布式复杂度。

## 2. 当前已确认约束

### 2.1 项目范围

项目需包含以下能力：

- 前端业务系统
- 后端服务
- MySQL 数据库
- 会员系统
- 权限系统
- 门店管理
- 商品与套餐
- 班次管理
- 月度任务计划
- 后续可扩展业务模块

### 2.2 已确认技术约束

- 数据库使用 `MySQL`
- `MySQL` 为独立运行实例，不通过 `Docker` 进行控制或启动
- 数据库连接信息、数据库名通过项目配置管理
- PC 端与移动端不拆成两个独立前端系统
- 前后端放在同一个项目仓库中维护
- 项目需支持“一套项目就绪后即可启动开发与部署”
- 前期即引入成熟且视觉质量较好的前端 UI 方案
- 需要持续维护开发记录文档，便于后续新会话承接上下文

## 3. 总体架构结论

本项目建议采用：

- `Monorepo` 单仓结构
- `前端一个应用 + 响应式适配 PC/H5`
- `后端一个服务`
- `模块化单体架构`
- `独立 MySQL`
- `Redis` 作为缓存与异步基础设施

不建议当前阶段采用微服务。

原因：

- 业务模块较多，但仍处于模型建设阶段
- 权限、门店、商品、班次、任务计划会产生大量跨模块联动
- 过早微服务化会显著抬高认证、事务、一致性、部署和排障成本
- 模块化单体足以支撑第一阶段业务上线，并为后续拆分保留空间

## 4. 技术选型

## 4.1 前端

建议技术栈：

- `Vue 3`
- `TypeScript`
- `Vite`
- `Vue Router`
- `Pinia`
- `UnoCSS`

UI 方案建议：

- 基础 UI 采用 `Naive UI`
- 表格与复杂中后台能力优先复用 `Naive UI` 生态能力
- 移动端交互样式在业务层做响应式适配
- 项目内封装一层 `Base*` 通用业务组件，避免后续被某个单一组件库绑死

## 4.2 后端

建议技术栈：

- `Node.js`
- `NestJS`
- `Prisma`
- `JWT + Refresh Token`
- `class-validator`
- `Swagger / OpenAPI`
- `BullMQ`
- `Redis`

## 4.3 数据库与基础设施

- 数据库：`MySQL 8.x`
- 缓存：`Redis`
- 文件存储：`MinIO / OSS / COS`
- 反向代理：`Nginx`
- 进程管理：`PM2` 或 `systemd`

说明：

- `MySQL` 独立运行，不纳入容器编排
- 应用仅通过配置读取数据库主机、端口、库名、账号和密码

## 6. 前端方案

PC 和移动端共用一个前端应用，不做独立系统。

这里的“共用”定义为：

- 共用业务逻辑
- 共用接口层
- 共用状态管理
- 共用路由体系
- 共用页面能力
- 视口和交互按场景适配 UI

不建议将 PC 和移动端强制做成完全同一视觉结构。

## 7. 后端方案

后端采用 `NestJS` 模块化单体。

建议初始模块如下：

- `auth`
- `iam`
- `member`
- `store`
- `product`
- `package`
- `schedule`
- `task-plan`
- `order`
- `system`
- `report`

## 8. 权限模型

建议一开始即采用：

- `RBAC`
- `数据权限`

功能权限：

- 菜单权限
- 页面权限
- 按钮权限
- API 权限

数据权限：

- 全部数据
- 所属组织
- 所属门店
- 本人数据
- 自定义门店范围

## 9. 数据模型设计原则

- 核心业务表统一包含 `id / created_at / updated_at / created_by / updated_by / deleted_at`
- 涉及归属关系的表尽量预留 `org_id / store_id`
- 不将多个业务状态压缩成单一 `status`
- 关系结构优先关系化建模，不用 JSON 代替关系表

## 10. 配置管理方案

项目通过环境配置管理关键运行参数。

至少包含：

- `APP_PORT`
- `WEB_PORT`
- `DB_HOST`
- `DB_PORT`
- `DB_NAME`
- `DB_USER`
- `DB_PASSWORD`
- `REDIS_HOST`
- `REDIS_PORT`
- `JWT_SECRET`
- `JWT_REFRESH_SECRET`
- `FILE_STORAGE_DRIVER`

## 11. 启动与部署方案

本地开发目标：

- 一个仓库完成前后端开发
- 不依赖 Docker 管理 MySQL
- 通过一条命令启动前端与后端开发服务

生产部署目标：

- 前端打包为静态资源
- `Nginx` 托管前端并反向代理接口
- 后端作为单独 Node 服务运行
- `MySQL` 独立部署与运维
- `Redis` 独立部署

## 12. 推荐优先开发模块顺序

1. 基础工程初始化
2. 登录鉴权与权限系统
3. 组织/门店体系
4. 会员系统基础档案
5. 商品与套餐
6. 班次管理
7. 月度任务计划
8. 订单与履约
9. 报表汇总

## 13. 当前待业务确认事项

1. 是否存在总部 - 区域 - 门店三级组织
2. 会员体系是否包含等级、积分、余额、优惠券
3. 商品套餐是否涉及库存、预约、核销
4. 班次是否仅为内部排班，还是与履约强关联
5. 月度任务计划按门店下发、按员工下发，还是两者都支持
6. 是否涉及财务统计、提成或分账
