# 蓝猫员工微信小程序开发方案

独立注册微信小程序，使用 Taro 4、Vue 3 和 TypeScript。小程序与 Web 共用 NestJS 后端、V2 账号、门店和业务数据。最终覆盖现有 Web 的业务内容和管理能力，按角色显示入口。前台动态码展示提供终端入口，开通和撤销纳入管理模块。

## 模块和交付顺序

| 阶段 | 模块 | 验收目标 |
| --- | --- | --- |
| 1 | 工程与账号 | 建立独立 Taro 工程、测试与生产配置、登录绑定、密码修改、会话失效和首页导航。配置 AppID 后联调微信登录。 |
| 2 | 员工高频操作 | 近期排班、上下班扫码、补卡、任务待办和历史、清单、异常、拍照提交、站内消息。覆盖跨夜、跨店和重试。 |
| 3 | 店长管理 | 排班、员工异动、补卡审核、任务派发、循环、补交、整改和复核、考勤查询与导出。验收本店和跨店权限。 |
| 4 | 总部运营 | 门店中心和工作台、经营看板、月报、使用分析、充值比武、任务统计、运营配置和同步状态。 |
| 5 | 总部管理与财务 | 岗位、组织及员工、账号角色、授权及日志、工资核算和职级。逐项核对导出、审计、审批和高权限操作。 |

每阶段以 Web 路由及其子页面为对照，逐项核对数据、操作、权限、异常状态和导出。手机上用分步表单和独立详情页承接复杂操作，列表采用服务端分页。批量和敏感操作沿用现有确认及审计口径。

## 工程和接口

- 在 monorepo 中建立独立 Taro 工程，以 apps/employee-mini 中的原生原型作为交互与 API 参考。试点页面迁移完成后再收敛原型目录。
- 登录、首页和消息放在主包，考勤、任务、门店运营、组织权限和财务按业务分包。共用 packages/shared 中的业务类型和常量，微信端使用 Taro 封装请求、上传、下载和导航。
- 后端提供微信登录码交换和绑定后的业务会话。AppSecret 由服务端配置。角色回收、换绑或离职后，服务端重新判断当前权限。
- Web 照片提交现有一次上传多张的能力。小程序先设计逐张上传和提交确认，将照片引用和提交记录在同一事务绑定，覆盖失败重试、过期清理和鉴权预览。
- 导出沿用后端生成文件的业务口径，在小程序验证下载、打开或分享能力。工资、考勤照片及任务附件沿用各自的权限。

## 联调与发布

工程、页面和 API 契约可与 Web 联调并行开展。真机登录和发布需要独立 AppID、适用类目、开发者权限、HTTPS 域名和隐私声明。iOS 与 Android 真机验收覆盖扫码、相机拒绝权限、弱网重试、动态码实时转发和顾客网误入。员工网络规则实测后启用强制校验，照片抽查和换绑审核纳入考勤上线验收。
