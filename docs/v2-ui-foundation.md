# V2 UI 与移动端基础规范

## 技术基线

- 保留 `Vue 3 + TypeScript + Vite`，避免重建前端工程和业务基础设施。
- 使用 Naive UI 承载表格、表单、弹窗、抽屉等复杂中后台组件，通过统一 `themeOverrides` 建立 BlueCat V2 视觉语言。
- 使用 UnoCSS 和项目级语义 CSS 变量处理布局、间距和响应式，不在业务页面散落设备判断。
- 使用 `@vueuse/core` 提供响应式断点和视口能力；使用 `@vueuse/motion` 提供声明式页面入场动效。
- 必须尊重 `prefers-reduced-motion`，用户选择减少动态效果时关闭非必要动画。

## 响应式策略

- `< 768px`：移动布局，侧边栏切换为左侧抽屉，筛选区和页面操作纵向排列。
- `768px - 1199px`：平板/小屏 PC，保留单套业务组件，根据可用宽度缩减列和卡片密度。
- `>= 1200px`：完整桌面中后台布局。
- 页面不得通过复制 `DesktopView` / `MobileView` 实现适配；数据请求、状态与交互必须复用。
- 复杂表格在移动端按业务重要性采用三种策略之一：关键字段卡片化、次要字段详情抽屉、确需宽表时局部横向滚动。
- 表单弹窗在窄屏使用近全屏尺寸，主操作按钮最小高度 40px，并预留底部安全区。

## 视觉与动效规则

- 基础设计令牌集中在 `apps/web/src/design/theme.ts` 和 `styles/global.css`。
- 页面只使用语义颜色，不在业务组件中重复硬编码品牌色。
- 动效用于路由入场、状态切换、数据刷新和层级展开，默认时长控制在 120–240ms。
- 不使用持续运动背景、阻塞操作的长动画或大量 WebGL 特效；经营系统首先保证信息密度、响应速度和低端手机可用性。
- hover 效果只在支持精确指针的设备启用，移动端不能依赖 hover 暴露操作。

## V2 页面开发约束

每个新页面合入前至少验证：

1. 1440×900 桌面视口。
2. 768×1024 平板视口。
3. 390×844 主流手机视口。
4. 320px 最小宽度无页面级横向溢出。
5. 键盘弹起时表单主操作仍可访问。
6. 减少动态效果模式下功能完整。

## 当前落地

- 已建立统一主题、品牌设计令牌、玻璃质感顶栏和新版导航品牌区。
- 桌面侧栏在移动端自动切换为抽屉导航。
- 页面路由接入轻量入场动效。
- 筛选区、指标卡、标题操作区、弹窗、表格和按钮已补充全局移动端规则。
- 当前应用内浏览器无法访问开发机 localhost，已通过 lint、typecheck 和生产构建验证代码；截图级视觉验收需在可访问本地服务的浏览器中补做。
