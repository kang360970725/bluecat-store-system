# V2 数据底座第一阶段设计

## 隔离与迁移策略

- V1 保持原模块和原表不变；V2 后端代码放在 `apps/server/src/modules/v2-data-platform`。
- V2 表统一使用 `v2_` 前缀。本阶段不让 V1 页面读取 V2 表，也不覆盖 V1 快照。
- migration 只新增表，允许 V1/V2 并行。生产切换前需完成黄金样本验收和至少一个完整月并行对账。
- 原始响应只追加或版本化保存；幂等键由来源、模块、门店、稳定业务键和 payload 哈希组成。

## 最小数据链路

1. `v2_ingest_batches`：请求参数、完整响应、采集窗口、分页和内容哈希。
2. `v2_raw_records`：原始明细、业务主键、原文哈希、发生/结算/更新时间。
3. `v2_rule_definitions`：规则编号、版本、说明和配置。
4. `v2_business_events`：标准事件、计入决策、过滤规则和原因。
5. `v2_event_links`：同源重复、跨源同业务及冲正关系。
6. `v2_metric_facts`：每个计入金额逐事件落事实，关联事件和规则。
7. `v2_reconciliation_runs`：门店和营业窗口的一次可重放对账。
8. `v2_reconciliation_items`：按来源、事件、规则和决策汇总的差异解释。
