# V2 主数据第一阶段

## 目标

V2 主数据不再依赖 V1 的组织、门店、岗位和员工表。第一阶段先建立能够支撑后续排班、权限、成本、目标与经营分析的稳定身份和任职关系。

## 数据模型

- `v2_organizations`：总部、区域、公司组织树。
- `v2_stores`：门店经营状态、开关店日期、营业日起点和基础资料。
- `v2_position_templates`：系统维护的默认岗位模板。
- `v2_store_positions`：门店岗位；可继承系统模板，也可由门店自行新增。
- `v2_employees`：员工自然人档案和全局状态。
- `v2_employments`：员工在某门店、某岗位的任职时间段。员工档案与任职关系分离，便于调店、兼岗和保留历史。
- `v2_employment_histories`：入职、调店、调岗、状态变化和离职的不可覆盖历史。

## 已实现接口

统一前缀：`/api/v2/master-data`

- `GET /overview`
- `POST /organizations`
- `POST /stores`
- `POST /position-templates`
- `GET /stores/:storeId/positions`
- `POST /stores/:storeId/positions/inherit`
- `POST /stores/:storeId/positions`
- `GET /employees?storeId=...`
- `POST /employees`

员工创建会在同一事务中写入员工档案、首段任职关系和 `HIRED` 历史。岗位继承采用 upsert，可重复执行且不会重复创建同一模板岗位。

## 后续扩展

下一阶段补充账号与 V2 权限主体、排班班次和经营目标模型，并逐步完善对应录入页面。生产部署前 migration 需统一验证，部署后执行只读接口和服务状态检查。

## 经营档案与员工操作扩展

- 员工支持调岗/调店：结束原主任职并创建新任职，同时记录变动前后数据。
- 员工支持离职：关闭所有有效任职、更新员工状态并记录离职历史。
- 请假支持时间段、类型、审核状态和重叠校验，不改写已产生的任职或班次数据。
- 门店经营档案新增主体资料、面积、座位数和租约周期。
- 成本配置支持固定金额、比例、公式和手工四种计算方式，并按生效时间版本化。
- 投入记录区分初始投入、追加投入、装修和设备等类型。
- 设备资产记录采购价、采购日期、数量、状态和预计换汰月数。
- 前端新增 `/v2-foundation` 只读概览，作为线上 V2 独立模块入口；复杂录入页面留待下一阶段逐项实现。
