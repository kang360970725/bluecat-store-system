# 员工考勤与运营任务需求

本文作为 2026 年 11 月 12 日的恢复和开发交接基线。系统复用现有 V2 门店、账号、员工、岗位、班次和排班。Web 端提供总部与门店管理，小程序作为员工操作入口。小程序可以独立发布或接入现有门店小程序，具体载体待定，业务后端共用。

## 员工考勤

- 员工首次绑定已验证的员工账号。换绑经审核后撤销旧绑定和会话，离职或停用后立即失去打卡资格。
- 门店授权终端展示短时动态码。员工扫码后，服务端校验账号、门店、已发布或锁定的班次、终端状态及服务器时间。多人可扫同一轮码，每个班次分别保留一条有效上班卡和下班卡。下班扫码是原实现的首版默认方案。
- 夜班按原排班日归属。跨店支援按实际发布的支援排班校验。打卡窗口由试点配置，迟到、早退、旷工阈值与工资联动待确认。
- 2026-11-20 起取消二维码终端打卡。店长在门店工作台维护一个或多个员工网络 BSSID；员工连接已登记 Wi-Fi 后，服务端结合微信绑定、门店排班（含加班）及时间窗口完成打卡校验。无法读取或匹配 BSSID 时只能走补卡审批。随机或风险抽查使用现场拍照、活体检测仍待后续评估。
- 员工按班次提交补卡时间及原因。授权人员按门店审核并填写说明，禁止自审，店长本人的申请交总部。原始记录和审核留痕。Web 支持终端开通及撤销、按日查询、月度 CSV 和审核历史。

## 运营任务与整改

- 按门店与岗位批量派发，每组共享一项任务。合资格员工并发认领时只允许一人成功。已认领但尚未提交且未逾期的任务可以由授权管理人员释放，保留原认领人及原因。
- 任务包含标题、说明、截止时间及可选检查清单。执行人逐项确认并记录异常，提交文字和照片。普通任务照片选填，整改至少一张。打回填写原因和新截止时间，原轮提交、照片和检查结果进入历史。
- 从原任务或具体异常项派发同店整改。整改保留原任务、检查项、异常说明及提交轮次，独立认领、提交及复核。
- 逾期后禁止正常提交。获授权的门店管理人员申请补交，同一任务至多一条待审申请。总部审批通过后指定新截止时间，原任务重新开放认领，原认领和截止时间留痕。
- 循环模板支持日、周、月，使用北京时间和持久化的计划时点去重。按月日期不足时落在月末。模板可暂停及恢复，服务恢复时跳过已过截止时间的轮次。
- 站内消息通知派发人和执行人。派发可配置最多五位已有目标门店管理权限的抄送人。待办页显示未来两小时截止任务。
- Web 提供待办和历史分页、管理筛选、按门店统计和 CSV。完成率按已确认完成数除以任务总数。统计按北京时间的任务截止日筛选。

## 权限和数据

- 岗位决定业务归属及默认角色，权限点决定操作，门店范围决定数据。管理权限不得随普通支援岗位跨店扩张。服务端按当前授权检查列表、详情、审批、附件及导出。
- 考勤查看、补卡审批、考勤导出、任务管理、统计及导出分别授权。导出同时要求对应查看权限。超级管理员通过账号直接授予。
- Web 提供有效权限预览，并记录角色权限、系统岗位模板角色绑定和账号门店范围变更。调岗、离职、撤权和旧会话需纳入验收。
- 任务证据私有存储。提交状态、照片和历史关联在同一事务保存。当前方案以原 Web 实现为参考，恢复时须与新仓库模型及迁移顺序核对。
